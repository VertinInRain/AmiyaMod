# 阿米娅模组 · 机制与用语词典（共享认知基线 v0.1）

> 用途：这是**"玩家自然语言 → 游戏实现语言"的翻译基准**。
> 你（设计者）用约定俗成的玩家语言描述效果，我用本文档的规则把它变成可实现的规格。
> 每条概念给四要素：**规则定义 / 生命周期 / 触发与结算 / 歧义处理**。
> 标注 `【核验】` = 尚未对照 v0.111.0 游戏内官方文本/代码确认，M0 阶段统一核实；核实后移除标记。
> 标注 `【待定夺】` = 需要作者（你）拍板的语义，见文末"歧义裁定表"。

---

## 1. 基本对象与牌堆

### 1.1 卡牌：模板 vs 实例
- **卡牌模板（Model）**：一张"卡"的定义——类型、费用、效果、稀有度、卡图、关键词。全游戏唯一。
- **卡牌实例（Card）**：出现在某局/某场战斗中的一张具体牌，有归属、位置（在哪个牌堆）、是否升级、附加词条、临时状态。
- 升级（升级/+）在模板层面区分：`基础版` 与 `升级版(+版)`，卡面数值走"动态变量"（见 §3），升级只换数值与可选的额外关键词，不重写效果。
- 设计文档写法"造成6/9点伤害"= 基础 6 / 升级后 9；"1/0 费"= 基础 1 费 / 升级后 0 费。

### 1.2 牌的归属堆（Pile）
| 堆 | 规则 | 生命周期 |
|---|---|---|
| 抽牌堆（Draw） | 从中抽牌上手 | 战斗开始时=洗牌后的初始牌组；抽空后**弃牌堆洗回**形成新的抽牌堆 |
| 手牌（Hand） | 唯一能主动打出的位置 | 回合结束弃光（**保留**的牌除外） |
| 弃牌堆（Discard） | 打出的牌、主动丢弃的牌的落点 | 战斗内持续存在；抽牌堆空时洗回 |
| 消耗堆（Exhaust） | **消耗**的牌被移出本场战斗 | 直到战斗结束 |
| （虚空牌 Void） | STS2 特有牌型，入抽牌堆后干扰抽牌 | `【核验】` 官方确切规则（抽到后的行为/自动消耗？） |

**注意**：弃牌堆≠消耗堆≠抽牌堆。设计里的"墓园：战斗开始时把带墓园词条的牌放入**弃牌堆**"利用的是弃牌堆机制；"感染：回合开始时若在**弃牌堆**中则变形"同理——两者都依赖对弃牌堆的**定向检索**。

### 1.3 一场战斗的时间轴（钩子点）
```
战斗开始(固有牌上手 / 墓园入弃牌堆 / 苍白赐福不触发首回合)
  → 回合开始(抽到5张[除非特殊] / 回合开始类效果 / 形态遗物触发)
  → 玩家的行动阶段(打出牌→耗能→结算→入弃牌堆; 可用牌循环)
  → 回合结束(丢弃非保留手牌 / 回合结束类效果 / 弃牌堆处理/感染检查按设计可能在回合开始)
  → 敌人回合(意图执行→伤害结算/格挡判定)
  → 下一回合…
```
`【核验】` 官方各阶段的先后次序（尤其是"感染"应挂在回合开始还是回合结束），以反编译代码为准。

## 2. 卡牌要素

### 2.1 类型（决定能否获得格挡/吃敏捷、吃力量等）
- **攻击牌（Attack）**：造成伤害，受力量/易伤/虚弱影响；与"攻击意图""荆棘"等交互。
- **技能牌（Skill）**：非攻击、非能力的牌；吃敏捷给格挡、虚弱不影响它。
- **能力牌（Power）**：打出后产生一个**持续整场战斗**的状态（Power），自身消耗离场。
- **诅咒/状态牌**：`【核验】` STS2 是否有"诅咒"类别及官方中文名；虚空牌归属。
- 类型影响"每打出**攻击牌**时…"这类条件判断，实现上按模板类型过滤。

### 2.2 费用与能量
- 每回合开始时能量恢复为上限（默认 3）；本回合未用完的能量**不**结转（除非有特殊机制）。
- 费用类型：固定费用（0/1/2/3…）、**X 费用**（打出时投入 0~当前能量，X=投入量，见歧义表④）、升级可减费。
- 例：`兔兔之踢 4费`=固定 4；`盛怒旋风 X`=投入多少能量决定效果规模。

### 2.3 目标（Target）
无目标（自身增益）/ 单体敌人 / 所有敌人 / 随机敌人 / 选择（选牌等）。
"对敌方全体"与"随机敌人造成N次"是不同目标语义，实现为不同命令。

### 2.4 稀有度
设计文档使用：初始 / 普通 / 罕见 / 稀有 / 先古。
`【核验】` STS2 官方稀有度枚举与"先古"对应关系（先古牌/先古遗物升级链的官方名称），M0 在 ModelDb/稀有度枚举中确认。

## 3. 数值、升级与作用域

### 3.1 动态变量（DynamicVar）
- 卡面文本中的数字用**变量**而非硬编码，如 `造成 {DAMAGE} 点伤害`；升级只改变量值，文本自动刷新。
- 好处：升级文本、易伤加成后的显示、附魔/增益改值都能正确反映。

### 3.2 作用域（决定"记不记得住"）
| 作用域 | 例子 | 实现要点 |
|---|---|---|
| 本回合 | 临时力量、活力 | 回合结束清除 |
| 本场战斗 | "本场战斗中每触发过一次形态转换"、黑冠、燃烬 | 战斗开始时创建的 Power/计数器，战斗结束销毁 |
| 本局游戏（跨战斗） | "永久获得最大生命"、"支援未来金币" | 存在角色/玩家存档状态上 |
| 词条永久性 | 领袖/魔王等词条被"不容拒绝"添加到所有打击防御 | 改的是**卡牌模板**或实例的持久词条列表 |

**实现模式**：跨回合/跨战斗的"次数统计"一律做成**显式计数器**（字段或计数 Power），挂到正确的生命周期事件上累加，绝不在效果里临时算。

## 4. 伤害与格挡管线（最重要）

### 4.1 一次"造成伤害"的完整路径
```
来源(攻击牌/状态/遗物…) → 选择目标 → 基础数值
  → 加减法修正(力量、临时力量、"牌组中每有一张魔王牌伤害+X"等)
  → 乘除法修正(易伤1.5× / 虚弱0.75× / 黑冠2× / 下回合伤害翻倍…)
  → 命中(目标是否仍在场) → 格挡吸收 → 未格挡伤害 → HP损失 → 致死检查(斩杀钩子)
```
- **力量（Strength）**：攻击牌的每次伤害 +力量值（多层"命中"的每一下都加）。
- **易伤**：受到的攻击伤害 ×1.5；**虚弱**：造成的攻击伤害 ×0.75。`【核验】` STS2 官方倍率与名称。
- 伤害修正分**加性**与**乘性**两类钩子——黑冠"伤害翻倍"属于乘性且**必须排除自伤**（旧版 bug 正是自伤也被翻倍）。

### 4.2 命中（Hit）与多次命中
- 一次"造成 X 点伤害"结算 = **一次命中**（一次伤害实例）。
- "额外命中一次 / 命中次数+N"= 把同一次伤害按规则拆成多次**独立的伤害结算**（每次重新走一遍管线）。
- **计数上限**（"最多三次/升级后最多五次"）指单次打出该牌时可命中的总次数封顶。
- 副作用差异要小心：多段命中会多次触发"每命中一次"类效果；荆棘/回击的触发粒度（每次攻击 vs 每次命中）`【核验】`。

### 4.3 格挡（Block）
- 格挡在**自己回合开始**清零（多数情况）；获得时机无限制。
- "成功格挡"的准确定义见歧义表②（完全格挡 vs 部分吸收）。
- 神魂坚韧之歌"本场战斗中每成功格挡过一次伤害，命中次数+1"的实现 = 战斗级计数器：订阅"你受到伤害结算"事件，按裁定口径累加，打出时命中数=基础+计数值。

## 5. 状态系统（Power/Status）

### 5.1 分类与关键属性
- 按效果方向：增益（Buff）/ 减益（Debuff）/ 中立。设计文档中文常混用"状态/能力"，实现上都叫 Power。
- **层数（Amount）与叠层策略**：数值型（力量+1/层）、存在型（无实体，1 层即生效）、计数型（魔王之唤 0→7）。
- **挂载对象**：敌人身上 / 玩家身上 / 全体；**可见性**：玩家可见（Buff/Debuff 图标）。
- 敌方状态与玩家状态同构，只是作用方向不同（如给敌人易伤 vs 给自己易伤）。

### 5.2 常见状态速查（已据中文 wiki 校准，2026-09）
力量(strength，可负) / 敏捷(dexterity，可负) / 易伤(vulnerable) / 虚弱(weak) / 脆弱(frail) / 中毒(poison) /
荆棘(thorns) / **覆甲(plating：回合结束时获得等量格挡、回合开始层数-1，"多层覆甲"的官方名)** / 人工制品(artifact) /
无实体(intangible：本回合所有伤害与生命减少降为1) / 再生(regen：回合结束回血，每回合-1) / 仪式(ritual：回合结束获得力量) /
活力(vigor：下一张攻击牌+X伤害)。
可直接当"实现积木"的原版状态：下回合格挡(block_next_turn)、下回合抽牌(draw_cards_next_turn)、下回合能量(energy_next_turn)、
免费攻击/技能/能力(free_attack/free_skill/free_power)、暗影步(shadow_step：下回合攻击双倍)、双倍伤害(double_damage) 等——M0 对齐官方 ID 后优先复用。
设计文档已涉及：**虚弱、易伤、无实体、覆甲、仪式、再生、活力、临时力量**。
`呼唤`（原版状态牌，作者确认）：回合结束时若在手牌则失去 6 生命。

### 5.3 本模组自创 Power（示例映射）
| Power | 行为 | 实现模式 |
|---|---|---|
| FormManagerPower 形态管理器 | 存当前形态/总切换次数，提供 TriggerFormSwitch | 战斗级 Power + 显式字段 |
| 魔王之唤(计数) | 到 7 层转魔王形态 | 计数 Power，叠层时检查阈值 |
| 黑冠 | 伤害×2(不含自伤)；每出 1 张牌自伤 3 | 乘性伤害钩子 + 打出牌事件钩子 |
| 燃烬 | 形态切换改为"消耗一张手牌" | 改写 TriggerFormSwitch 分支 |
| 裁决 | 获得魔王之唤时对全体 9 伤 | 监听"获得魔王之唤"事件 |

## 7. 本模组自定义词条（操作定义，随设计确认）

| 词条 | 触发规则（按设计文档） | 实现挂钩点 |
|---|---|---|
| 魔王 | 打出带魔王词条的牌 → 获得 1 层魔王之唤 | 打出牌事件 → 词条检查 |
| 感染 | 回合**结束**时，若带感染词条的牌在**弃牌堆**中 → 变形成 打击/防御（作者 2026-09 修订：原"回合开始"改为回合结束） | 回合结束事件 + 弃牌堆检索 + 变形命令 |
| ↳ 变形规则 | **移除全部词条**（感染及其他所有词条），保留升级状态（→打击+/防御+） | 作者裁定 2026-09 |
| 领袖 | 打出带领袖词条的牌，且是本回合**第奇数张**打出的牌 → 结算后放入**抽牌堆**（随机洗入）；**若该牌带消耗词条则照常消耗，领袖不生效**（作者 2026-09 修订） | 打出计数 + 落堆位置改写 |
| 墓园 | 战斗开始时，把带墓园词条的牌放入**弃牌堆** | 战斗开始事件 |

## 8. 特殊句式 → 实现模式库（设计文档逐句拆解参考）

1. `造成6/9点伤害，本场战斗每触发过一次形态转换额外命中一次(最多3/5)` → 战斗计数 + 命中数 = min(1+计数, 上限)，打出的瞬间**快照**计数。
2. `若敌人意图不是攻击，则对其造成两次伤害` → 需要读**敌方意图(Intent)**枚举 `【核验】意图分类`。
3. `重放2/3`、`升级后获得重放1` → 见歧义表③。
4. `抽牌至抽到第一张打击/防御` → 条件抽牌：逐张抽直到命中条件或抽空。
5. `X：对所有敌人造成1点伤害，获得3/4点临时力量，重放X次` → X 费 + 按投入能量决定重放次数。
6. `打出抽牌堆和手牌中所有打击和防御` → 从非手牌位置打出（"青色怒火"），需确认该机制对"打出"事件/词条的统一性。
7. `回合开始时，若这张牌在消耗堆中，将其打出`（我心永随/求而不得之物）→ 消耗堆自激活。
8. `斩杀时，永久获得3/4点最大生命`（血刃高悬）→ 致死钩子 + 跨战斗属性修改。
9. `本回合为你的所有手牌添加虚无`（火烧云）→ 手牌实例批量加临时词条。
10. `获得与已损失生命值等量的护盾`、`失去生命` → HP 损失类（区别于"受到伤害"，不走格挡）。
11. `选择任意张手牌，变为防御+`（勘破虚妄）→ 目标选择 + 模板替换（含升级态）。
12. `消耗所有魔王之唤，每消耗一层获得12/15点格挡` → 读层→清零→按层数结算。
13. `失去1点临时力量`（怒号光明前置）→ 需要**精确的"临时力量"引用**（降的是临时部分）。
14. `每回合开始时将一张存续先兆加入手牌`（预言显像）→ 生成+加入，需处理复制来源。
15. `首回合不触发`（苍白赐福）→ 遗物触发带"是否首回合"条件。

## 9. 歧义裁定表（作者已确认，2026-09）

| # | 句式/概念 | 裁定结果 |
|---|---|---|
| ① | 额外命中一次 | **一次独立的伤害结算**：重新完整走过伤害管线（力量/易伤/格挡等），不是整张牌重打 |
| ② | 成功格挡 | 敌方对你的一次伤害被**完全格挡**（实际穿过伤害为 0）才算一次成功格挡 |
| ③ | 重放 X | 打出后再**完整打出 X 次**（免费、重跑全部打出效果），**计入"打出"类钩子**（魔王/领袖等均触发） |
| ④ | X 费 | X = 打出时**投入的能量数**（0~当前能量），投 0 时效果量为 0 但仍视为打出 |
| ⑤ | 感染变形 | 变形为**纯粹**的打击/防御：**移除全部词条**（感染及其他所有词条），**保留升级状态**（→打击+/防御+） |

## 10. 建立与维护方法（防止认知偏差）

1. **M0 权威校准**：从游戏安装中提取官方关键词/状态/稀有度/意图的官方文本与反编译代码，逐条修正本文档，移除 `【核验】`。
2. **每张卡落地前**：你给句式 → 我按本文档翻译成规格（含边界与触发点）→ 你确认 → 实现 → 游戏内实测对照。
3. **测试用例化**：特殊句式的边界（首回合、0层、空堆、随机目标为空等）写成可勾选清单，实机逐项验证。
4. 你对**设计意图**有最终解释权；我对**官方机制**负责核实。冲突时以官方机制为准并向你说明。
